# C方案：轻量验证（Verification, not Analysis）

## 定位与原则

C方案的本质一句话：**用公开信息，低成本验证"这家公司是不是在按它说的做"。**

- **是验证，不是分析**：不建模、不预测、不跑现场、不做行业深度认知
- **只对卫星仓最终候选 2-3 只执行**（L7筛 → L1-L6报告 → 筛到2-3只 → C方案验证决定最终买谁）
- **建立在L1-L6报告之上，是报告的"复核层"**：先有L1-L6报告，再跑C方案。C方案不是从零开始，而是**验证报告里写过的具体判断**（详见下节）
- **不单独决定买卖**：它验证 L1-L6 报告的核心假设。验证结果与报告冲突时，**以验证为准**，并在报告中标注冲突点
- **它是护栏，不是alpha**：L1-L6筛出"健康公司"，C方案筛出"被错杀/言行一致"的公司。便宜体检单筛不出被错杀，后者靠C方案补

## 与L1-L6报告的关系（前置条件）

**执行顺序：先有L1-L6报告，再跑C方案。** 没有报告的股票，先跑 `stock-report-tab` 生成报告，或明确标注"此验证无L1-L6基础，仅供参考"。

**执行流程：**
1. 先读该股已有L1-L6报告（`stock-learning/stocks-analysis/{市场}/{L5分类}/{简称}_{代码}_分析报告.html`）
2. 从报告中提取**待验证的具体判断**，报告里有现成素材的tab：
   - **L6 资金面信号**（北向、机构持仓、融资、大股东增减持）→ C方案②③④去核实这些信号的细节和最新变化
   - **L6 风险评估-管理层增减持记录** → C方案②深挖
   - **L6 三情景表（乐观/中性/悲观）** → C方案①核实"中性假设"与公司指引/激励目标是否一致、是否在轨道上
   - **L2 排雷清单** → C方案③互动问答重点找对应风险的问题
3. C方案只验证报告里的判断，**不重复报告已做的基础财务分析**
4. 报告里没有、但C方案发现的**新信号**（如新公告、新问答、股东户数变化）→ 作为增量写入验证报告

**输出时**：验证报告须引用L1-L6报告的具体tab（如"验证了L6资金面信号'北向减持'，实际是……"），并标注冲突点。

## 适用范围与A股/ASX差异

| 步骤 | A股 | ASX |
|------|-----|-----|
| ① 兑现记录 | 业绩预告vs指引、股权激励目标vs实际、募投进度 | 公司guidance vs实际、扩产/并购承诺vs落地、季度报告vs指引 |
| ② 内部人动向 | 董监高/大股东增减持、回购、质押 | director trading公告 |
| ③ 互动一问 | 互动易/e互动公开问答（**我直接查**） | **生成IR邮件，用户发**（我无法发邮件） |
| ④ 筹码与机构 | 股东户数、调研纪要、机构持仓 | 机构持仓变化、top 20股东 |
| ⑤ 业绩说明会/AGM | 业绩说明会文字实录 | **AGM现场（用户执行，持仓后）** |

## 数据来源（优先级从高到低）

1. **websearch 实时搜索** — 优先。财务/公告/增减持/股东户数/调研纪要/互动问答摘要，记录来源和日期
2. **用户提供** — 用户给的持仓、IR回复、公告截图
3. **知识内已知数据** — 仅历史参考，必须标注"历史参考"

**抓取失败的优雅处理**：互动易/e互动、东方财富F10等动态网页直接抓取易失败 → 改用 websearch 找问答摘要、券商点评、财经媒体转述；仍搜不到就标 **"数据待补充"**（灰色），**禁止编造**。

关键入口（用于提示用户或搜索关键词）：
- 深交所互动易：irm.cninfo.com.cn（搜"公司名 互动易 问答"）
- 上交所e互动：sns.sseinfo.com
- 股东户数：东方财富 F10 → 股东研究 → 股东户数（搜"公司名 股东户数 2026"）
- 调研纪要：巨潮搜"投资者关系活动记录表"
- 增减持：东方财富增减持栏（搜"公司名 董监高 增减持"）

## 五步流程

### 第一步：兑现记录（约30分钟）

**目标**：管理层说过的话 vs 实际做到的事。兑现记录是判断管理层最便宜的指标。

**A股数据源**：
- 业绩预告/业绩快报 vs 此前年报/中报里的指引
- 股权激励解锁条件 vs 实际完成
- 募投项目公告 vs 投产进度

**ASX数据源**：
- 年初给的年度guidance vs 实际业绩
- 扩产/并购承诺 vs 落地时间表
- 季度生产报告 vs 年度指引（如铜矿、矿企）

**输出**：承诺兑现表

| 承诺时间 | 承诺内容 | 应兑现时间 | 实际结果 | 评价 |
|---------|---------|-----------|---------|------|
| {日期} | {承诺} | {日期} | {实际} | 兑现/落空/部分 |

**信号解读**：
- 全部兑现或绝大多数兑现 → 强正面
- 部分兑现 → 中性偏正
- **连续2次以上落空 → 重大负面**（管理层信用破产，直接影响卫星仓去留）

### 第二步：内部人动向（约15分钟）

**目标**：内部人比任何人都懂自己公司，看他们的真金白银方向。

**A股**：董监高/大股东增减持公告、回购进展、股权质押比例
**ASX**：director trading披露（董事买入=强正面）

**信号解读**：
- 内部人/大股东净买入 + 回购 → 正面
- 集中减持（尤其高位/连续） → 负面
- 高比例质押 → 负面

### 第三步：互动一问（约30分钟）——看公司回避什么

**A股（我可直接执行）**：翻互动易/e互动历史问答
- 公司**回避了哪些问题**：答非所问、口径前后矛盾 → 红旗
- 别的散户/机构在担心什么 → 就是你要验证的风险点
- 记录最近3-5条有信息量的问答

**ASX（用户人工）**：生成IR邮件模板（见附录），用户发送，把回复粘回对话后我再判断

### 第四步：筹码与机构（约20分钟）

**A股**：
- **股东户数趋势**：连续下降 + 股价震荡 = 筹码集中 = 有人在收（正面）；户数上升 = 发散（中性偏负）
- **调研纪要**：最近机构调研时间、问了什么问题（聪明钱在关心什么）

**ASX**：机构持仓变化、top 20 股东名单（公开披露）

### 第五步：业绩说明会/AGM（持仓后可选）

**A股**：业绩说明会文字实录，看管理层对未来订单/产能/分红的口径 vs 公告一致性
**ASX**：AGM现场提问（用户执行），一年一次

## 结论框架

### 每步verdict

正面 / 中性 / 负面 + 一句话依据 + 数据来源日期

### 评分（10分制，可读性辅助）

五步各 0-2 分（负面0 / 中性1 / 正面2），总分 0-10。**分数只是五步判断的透明包装，不是独立测量**——真正决定结论的是红色信号本身。

| 总分 | 等级 | 含义 |
|------|------|------|
| 8-10 | 绿 | 言行一致 |
| 5-7 | 橙 | 部分存疑 |
| 0-4 | 红 | 言行不一致 |

**重大负面一票否决**：只要出现任一重大负面（连续落空 / 集中减持 / 高质押 / 回避关键问题），无论总分多少，直接 verdict-bad。

### 总verdict

| 条件 | 结论 | 颜色 |
|------|------|------|
| ≥4正面且无重大负面 | **言行一致** | verdict-ok（绿） |
| 2-3正面且无重大负面 | **部分存疑，结合报告判断** | verdict-caution（橙） |
| 任一重大负面（连续落空/集中减持/高质押/回避关键问题） | **言行不一致，剔除** | verdict-bad（红） |

**卫星仓规则联动**：只有 verdict-ok 或 verdict-caution 才进入实盘候选；verdict-bad 直接剔除，不进入建仓流程。

## 输出

### 路径

`stock-learning/stocks-analysis/验证/{股票简称}_{代码}_C方案验证.html`

> 示例：`stock-learning/stocks-analysis/验证/新和成_002001_C方案验证.html`

### 单页HTML结构（比stock-report-tab精简，无tab）

```
body (bg:#f5f5f5)
  .report-wrap (max-width:800px, bg:#fff)
    h1 {股票简称}({代码}) C方案验证 + .subtitle + .meta（YYYY-MM-DD）
    【结论一句话】（报告最顶部，最大字号，一句话说清该怎么做）
    总verdict（verdict-ok/caution/bad，居中圆角框，含总分X/10）
    五步结论汇总表（步骤/得分/verdict/一句话依据）
    每步详情（小标题 + 证据表/要点 + 结论框）
    与L1-L6报告冲突标注（如有）
    【验证了报告里的哪些判断】（表格：报告的tab/报告写的判断/C方案验证结果）
    用户待办清单（IR邮件/AGM/渠道验证，用highlight-box）
    怎么读这份报告（三段话：结论在哪/依据在哪/你该做什么）
    数据来源与日期（websearch条目+日期）
```

**结论一句话示例**：
- 绿："这家公司说的基本都做到了，内部人还在买，可以进入卫星候选池。"
- 橙："大部分兑现，但XX有疑点，先补一个渠道验证再决定。"
- 红："连续两次没兑现承诺 + 大股东减持，言行不一致，剔除，不进入建仓。"

**CSS**：复用 `stock-report-tab` 的类名和样式准则（summary-box浅黄、danger-box浅红、highlight-box浅蓝、verdict三色），h2 font-size 18px 带下边框，h3 15px，table同款。

### 内容填充规则

- **meta日期**统一 `YYYY-MM-DD`
- **报告依赖**：验证报告须引用已存在的L1-L6报告路径和tab（"验证了L6资金面信号/三情景/风险表"）；若无报告，顶部明确标注"无L1-L6基础，仅供参考"，并建议先跑 `stock-report-tab`
- 每步证据必须带**数据来源和日期**，搜索到的标来源，缺失的标"数据待补充"（灰色），不参与判定
- **用户待办清单必须单独列出**：ASX的IR邮件、AGM、可选的渠道验证（经销商/客户访谈——A方案性质，标注为增强项）
- 报告末尾加一句原则提醒："C方案是验证不是分析，不单独决定买卖；结论冲突以验证为准"
- **每一句verdict必须用大白话写**，禁术语堆砌，要让看不懂财报的人也能知道该做什么
